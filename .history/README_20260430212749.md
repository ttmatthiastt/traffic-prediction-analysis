## Problem

- Forecast the **next time‑step total traffic** at an intersection using historical sensor data.
- Use only inputs available at prediction time: current and recent traffic counts, time of day, and day of week. 

## Methods

- Performed **feature engineering** from raw timestamps:
  - Parsed clock time into hour of day, day index (0–6), and weekend flag.
  - Created lag features for Total traffic (e.g. Total at t−1, t−2, t−3).
- Built a **time‑series forecasting pipeline** with a chronological train/test split:
  - First 80% of the series for training, last 20% for testing (no shuffling).[file:90]  
- Compared three models:
  - Naive baseline: predicts `next_total = current_total`.
  - Linear Regression on time + lag features.
  - Random Forest Regressor on the same feature set.[file:90]  

## Results

- On the held‑out test set:
  - **Baseline**: MAE ≈ 27.64, RMSE ≈ 38.60.
  - **Linear Regression**: MAE ≈ 25.66, RMSE ≈ 34.23.
  - **Random Forest**: MAE ≈ 19.50, RMSE ≈ 26.81.[file:90]  
- The Random Forest model **captures the daily pattern** well:
  - Follows nighttime low, morning ramp‑up, and midday plateau.
  - Smooths very sharp local spikes, which is expected for an ensemble using only a few lag and time‑of‑day features.[file:90]  
- The forecasting notebook includes **plots of actual vs predicted** Total traffic for sample windows in the test period, illustrating how closely the model tracks the true signal.[file:90]
